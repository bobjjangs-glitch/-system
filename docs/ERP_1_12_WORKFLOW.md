# 자체 ERP 전표 확인·지역별 배차 — 1.12.0(22)

## 사용 흐름

1. 관리자 **전표** 화면을 열면 거래처·품목 목록을 자동으로 읽습니다. 활성 화면에서는 60초 간격/앱 복귀 때 갱신하고, 거래처·품목 검색창을 열거나 검색어를 입력할 때는 ERP에 직접 조회합니다. 정상 사용 중 별도 목록 가져오기 버튼을 누르지 않습니다. 전체 목록의 최근 갱신은 서버에서 공유하지만 검색 결과는 이 캐시로 대체하지 않습니다.
2. **판매 조회 일자 → 일자 조회** 한 번으로 해당 날짜의 판매전표 전체를 페이지를 따라 읽습니다. 화면에서 별도의 가져오기 버튼을 반복하지 않습니다. ERP 판매일자와 전표번호 날짜를 함께 확인하며 작성중·확정·취소 전표를 모두 보여 줍니다. 하루 최대 2,000건을 지원하고 초과/부분 응답은 잘린 성공 목록으로 표시하지 않습니다.
3. **전표번호**를 누르면 해당 전표를 ERP에 다시 직접 조회합니다. 목록을 읽은 뒤 ERP에서 수정한 내용도 이때 반영됩니다. 공급자·거래처·주소·연락처·판매일자·소매/도매·결제수단/선택 계좌·ERP 고객/차량 원본 정보·품목코드·규격·패턴·과세 구분·수량·단가·공급가액·합계·공장도가·DC율·품목/전표 적요를 채웁니다. ERP에 없는 값은 임의로 만들지 않습니다.
4. 배송주소·연락처·요청사항을 확인하고 **확인하고 전표 등록** 한 번으로 앱의 배송 전표에 등록합니다. 확인 중 ERP가 바뀌면 등록을 중단하고 최신 내용을 다시 확인하도록 합니다. 중복 확인은 배송지를 중복 생성하지 않습니다. 취소·반품은 배차하지 않습니다. 여러 전표를 선택해 한 번에 등록하는 기능도 유지합니다.
5. **등록한 전표로 지역별 배차 추천**을 누르면 구·시·군별 그룹을 우선하는 추천을 실제로 생성합니다. 주소 위치를 확인하고 기사 한도, 회사 출발·복귀, 배송지 10분 체류를 반영합니다. 수기 배정한 코스는 유지합니다. 실시간 교통은 서버의 Naver Directions 인증과 출발시각 설정이 필요하며 인증 실패를 실시간 성공으로 표시하지 않습니다.

명세서 메뉴에서는 `20261106-49`, `26/11/6-49`, `SL-20261106-0049` 같은 원본/동등 번호로 직접 찾을 수 있습니다. 정확한 원본 번호가 존재하면 우선하고, 같은 날짜·순번이 여러 건이면 자동으로 하나를 선택하지 않습니다. 과거에 등록한 전표의 명세서는 등록 당시 보존한 원본을 보여 줍니다.

조회/기존 전표 등록은 회사 ERP 판매를 다시 작성하거나 확정·재고 차감을 실행하지 않습니다. 새 수기 판매전표 작성은 ERP의 작성중 전표로 저장하고, 확정·재고 처리는 기존 ERP에서 진행합니다.

## 관리자 삭제

- 판매조회 JSON 목록은 목록 화면 또는 **내역 → 전표 삭제**에서 삭제할 수 있습니다. 조회 JSON의 `sales-list` 상태가 삭제 허용 목록에서 빠져 있던 문제를 수정했습니다. 조회 목록 삭제는 이미 등록한 배송지와 ERP 원본을 유지합니다.
- 등록한 앱 전표는 연결된 배송지까지 삭제할 수 있습니다. 운행·완료 상태라는 이유로 관리자 삭제를 막지 않습니다. 확인창에 함께 삭제되는 범위를 표시합니다.
- 배송지 삭제는 남은 코스의 순번·거리·시간·경로를 갱신합니다. 이 갱신은 정적 예상으로 표시하고 과거 실시간 교통 ETA를 재사용하지 않습니다. 마지막 배송지를 지우면 빈 코스와 연결 위치 기록을 정리합니다.
- 코스 삭제는 해당 코스/위치 기록을 지우고 남은 배송지는 보관합니다. 배송 대기 건은 미배차로 되돌립니다.
- 기사 삭제는 기사 계정·PIN·로그인 세션·위치 기록과 연결 코스를 삭제합니다. 배송지는 보관하며 배송 대기 건은 미배차로 되돌립니다.
- 삭제 API는 서버에서도 관리자만 허용합니다. 이 기능은 앱 데이터 삭제이며 회사 ERP 원본 판매/재고를 삭제하지 않습니다. 삭제한 앱 데이터는 복구할 수 없습니다.

## 사진 전표 금액

품명·수량만 읽던 분석과 자동 채우기를 보완해 단가·금액·합계·공장도가 열을 위치로 읽고 저장/재열기까지 유지합니다. 숫자 칸 안에서만 `O/0`, `I/1` 혼동과 천 단위 구분자를 보정합니다. 수량×단가, 금액/합계, 품목 합계/총합계를 대조합니다. 잔액·계좌번호를 전표 합계로 사용하지 않습니다.

인식값이 다르면 원본 숫자를 보존하고 확인을 요청합니다. 사진에 인쇄된 단가에 부가세를 임의로 더하지 않으며, 운영자가 입력한 보정값을 재인식으로 덮어쓰지 않습니다. 공급가액·부가세를 모르는 전표도 인쇄된 합계는 그대로 표시하고 모르는 값은 0원 대신 확인 필요로 구분합니다. 흐린 사진의 인식률·5초 이내 완료를 모든 실기기에서 보장한다는 의미는 아닙니다. 기존 기기 내 한국어 OCR과 제한시간은 유지하고 별도 외부 OCR 요청은 추가하지 않았습니다.

## 설치

서버·ERP PHP·APK를 함께 업데이트합니다. 이전 서버에서는 새로운 전체 확인 흐름을 사용하지 않도록 갱신 안내를 표시합니다. Render 인증/배포는 사용자가 담당하기로 했습니다.

1. ERP 자동 설치 ZIP의 `bareun_update_1_12.php` 하나를 FTP의 기존 `tire/erp` 폴더에 올립니다. `index.php`와 `inc`가 있는 위치입니다.
2. ERP 관리자로 로그인하고 `https://bobjjangs1231.dothome.co.kr/tire/erp/bareun_update_1_12.php`를 엽니다. **백업하고 ERP 파일 5개 적용**을 누릅니다. 백업·무결성 검사·교체·실패 시 복구를 자동 처리하며 성공하면 설치기는 삭제됩니다. 기존 DB 설정·연결키·판매·재고는 변경하지 않습니다.
3. Render의 소스 브랜치 `codex/free-node-test`에서 이 버전 커밋을 배포합니다. 기존 `COMPANY_ERP_API_URL`·`COMPANY_ERP_TOKEN`을 유지합니다. E카운트 환경변수는 더 이상 사용하지 않습니다. 무료 서버의 필요한 기존 자료는 배포 전에 보관하세요.
4. 1.12.0(22) APK를 기존 앱 위에 설치합니다. ERP 전표 `20261106-48`·`20261106-49`를 ERP 화면과 앱에서 대조합니다.

`python3 scripts/package-company-erp-installer.py /workspace/artifacts`로 같은 설치 패키지를 만들 수 있습니다. 수동 교체 ZIP은 `scripts/package-company-erp.py`로 만들며 PHP 5개만 포함합니다. 비밀키/DB 설정은 두 패키지 모두 포함하지 않습니다.

## 검증 범위

서버 자동 테스트 211개와 실제 PHP 8.3.36·MariaDB 10.11·모바일 브라우저의 가상 ERP를 사용했습니다. 날짜/번호 날짜 차이, 65건 페이지 조회, 전체 내용/결제 계좌 매핑, SL/순번 0/날짜 0 표기 차이, 자동 목록 갱신, 최신 전표를 한 번 확인해 등록, 변경된 전표 거절, 중복/재고 보존, 지역별 실제 추천 생성, 관리자 JSON 삭제, 기사 권한 거절을 검증했습니다. 접두사 없는 ERP 테이블 조회도 별도 실제 PHP/DB로 검증했습니다.

제공된 예시 PDF의 내장 텍스트·좌표에서는 수량 2, 단가 368,000, 합계 736,000, 공장도가 451,000, 전표 총합계 736,000이 일치했습니다. 인증된 전표 업로드·재열기와 320px 모바일 검토 화면에서도 같은 단가·합계를 표시하고 미확인 값을 0원으로 바꾸지 않는 것을 추가 확인했습니다. 이 확인은 실제 휴대폰 카메라 OCR 검증과 구별합니다. 실제 회사 ERP의 인증된 자료·FTP 운영 파일·실물 휴대폰은 이 작업 환경에서 직접 확인하지 못했습니다.
