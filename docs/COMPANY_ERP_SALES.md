# 판매조회 목록·휴대폰 거래명세서 — 1.14.0(24)

현재 사용·설치·오류 구분은 [오늘 판매내역 자동 조회](ERP_1_14_AUTO_SALES.md)를 확인하세요. 전표 화면을 열면 한국 날짜의 오늘 판매내역 전체를 자동으로 읽으며, 날짜 검색이나 조회 버튼이 필수 단계가 아닙니다.

1. **오늘 판매조회**에서 회사 ERP에 오늘 등록된 전체 목록을 확인합니다. 오늘 20건이면 20건을 표시하며 1분마다 새 자료를 확인합니다.
2. 전표 카드를 누르면 원본 문서 ID로 최신 수정본을 읽어 판매전표 확인 화면에 채웁니다. `20261106-72`와 `26/11/06-72`는 같은 전표로 검색합니다.
3. 거래처·주소·연락처·품목·수량·단가·공급가액·부가세·합계·공장도가·DC율·적요 등 원본 항목을 세로 화면에서 확인합니다. 없는 금액은 미확인으로 유지합니다.
4. **확인하고 전표 등록**으로 앱 전표와 배송지를 등록하고 **등록한 전표로 지역별 배차 추천**으로 이어갑니다. 자동 목록 조회만으로 JSON 내역·배송지·ERP 판매·재고를 생성하지 않습니다.
5. 관리자 **명세서**, **내역**, 배송 상세에서 등록 당시 명세서를 다시 볼 수 있습니다. 기존 저장 목록과 삭제 기능도 유지합니다.

현재 연결 대상 주소를 화면에 표시하고, 자체 ERP의 원본 저장소·PHP 연동 버전을 검사합니다. 구형 PHP·다른 저장소·조회 실패를 정상 0건으로 표시하지 않습니다. 외부 E카운트 API 호출은 없습니다. 자체 DB의 `erp_ecount_*` 이름은 로컬 보관 자료를 뜻합니다.

PHP 1.13 이상이 정상 설치됐다면 기존 도우미와 연결키를 유지하고 Node·APK 1.14를 적용합니다. 구형·누락 PHP는 최신 릴리스의 7개를 함께 적용합니다. 실제 원본 조회 설치와 ID 진단은 [원본 연결 안내](ERP_1_13_NATIVE.md)를 참고하세요.

원본에서 읽어 등록한 전표는 ERP 판매 확정·재고 차감·수금을 다시 실행하지 않습니다. 새 수기 판매 입력은 별도 일반 ERP 작성중 전표 흐름입니다. 앱 삭제는 앱 데이터에 적용하고 ERP 원본은 삭제하지 않습니다. 보관 명세서·중복 기록은 영속 `APP_DATA_DIR`로 유지합니다.
