# 판매조회 목록 · 휴대폰 거래명세서 — 1.10.0(20)

## 사용하는 순서

1. 관리자 **전표 → 판매 조회 일자 → 판매조회 내역 가져오기**를 누릅니다.
2. 가져온 전표가 목록에 표시됩니다. 전표번호·거래처·주소·품목으로 검색할 수 있습니다. 작성중·확정·취소·반품과 이미 배차 등록한 전표를 구분합니다.
3. **전표번호**를 누르면 휴대폰 안에서 거래명세서를 엽니다. ERP에 따로 로그인하거나 외부 페이지로 이동하지 않습니다. 긴 품목표는 좌우로 밀어 확인합니다.
4. 필요한 경우 명세서 아래에서 배차용 배송주소·연락처·요청사항을 보정합니다. ERP 원본 정보는 수정하지 않습니다.
5. 체크박스로 배송할 전표를 골라 **선택 N건 배차 대기에 등록**을 누릅니다. 선택한 건만 배송지로 생성되고 나머지는 목록에 남습니다. 이후 관리자 배차 화면에서 기사에게 배정합니다.
6. **마지막 판매조회 목록 보기**, 관리자 **내역 → 판매전표·명세서 보기**, **배송 상세 → 거래명세서 보기**에서 다시 확인합니다.

조회만 해서는 배송지를 만들지 않습니다. 최근 조회 시각을 표시하며, 재조회 버튼을 누르면 ERP의 최신 판매내역으로 갱신합니다. 이미 등록된 건은 중복으로 등록하지 않습니다. 작성중 전표는 명시된 상태로 배송에 사용할 수 있고 ERP 판매 확정·재고·수금은 기존 ERP에서 처리합니다. 취소·반품/0 이하 수량·음수 금액 전표는 목록에서 확인할 수 있으나 배차할 수 없습니다.

## 명세서에 표시하는 항목

- 전표번호·판매일자·상태, 판매구분(소매/도매), 결제방법(ERP에 있는 경우), 고객명·차량번호·취소사유
- 공급자·공급받는자 상호, 사업자등록번호, 대표자, 주소·전화
- 실제 배송 거래처, 배송주소·연락처, 거래처코드, 요청사항
- 품목코드·품명·규격·패턴·수량, **ERP 전표에 저장된 단가·공급가액**, 적요, 공장도가, DC율
- 품목별 합계와 전표 공급가액·부가세·총합계

ERP 전표의 단가와 금액은 상품의 현재 단가로 덮어쓰지 않습니다. 행별 합계가 원본에 없는 경우 공급가액과 과세 구분으로 계산한 참고값임을 표시하고, **전표 총액은 ERP 원본**을 유지합니다. 공장도가를 원가/매입가로 바꾸어 표시하지 않습니다. ERP 품목의 `factory_price`/`list_price`, 기존 전표 행의 `list_price`, 앱 작성 전표의 별도 공장도가 스냅샷만 사용합니다. 실제 원본에 없는 값은 미등록으로 표시합니다.

새 전표의 품목 검색에서는 거래처 기본 소매/도매 단가에 수량을 적용해 단가·공급가액·부가세 포함 합계를 채웁니다. 공장도가와 소매·도매 단가를 검색 결과에서 구분합니다. 공장도가를 직접 입력할 수 있으며 DC율은 공장도가, 없으면 ERP 소매 기준가에 적용합니다. 수동으로 고친 단가는 거래처 변경 시 자동으로 덮어쓰지 않습니다.

## 설치와 갱신

**새 앱·Node 서버·PHP 연동 파일 5개를 함께 갱신해야 합니다.** 이전 파일이 명세서/단가 항목을 지원하지 않으면 빈 값으로 정상 조회된 것처럼 표시하지 않고 업데이트 오류를 안내합니다. 이전 Node 서버를 사용하는 새 앱은 서버 배포가 필요하다고 표시합니다.

1. ERP/DB를 백업하고 제공 ZIP의 `tire/erp` 아래 PHP 5개를 같은 경로에 함께 교체합니다. 기존 DB 설정 파일은 덮어쓰지 않습니다.
2. ERP 관리자로 `dispatch_setup.php`에 로그인해 **앱 판매 작성 허용 · 저장소 준비**를 다시 누릅니다. 새 공장도가 스냅샷 열을 준비합니다. **기존 연결키는 유지**합니다.
3. Render의 `codex/free-node-test` 최신 소스를 수동 배포한 뒤 새 Android APK를 기존 앱 위에 설치합니다.
4. 실제 회사 전표 한 건을 ERP와 대조한 뒤 필요한 전표만 등록합니다.

목록과 등록 당시 명세서는 서버의 보호된 업로드/DB에 저장합니다. `APP_DATA_DIR`을 영속 보관하세요. 무료 Render 재배포로 임시 DB가 초기화되면 목록·등록 기록도 사라질 수 있습니다. 앱에서 배송지/목록을 삭제해도 ERP 원본을 삭제·취소하지 않습니다. 선택 등록 전 최신 ERP 지문을 확인하지만 ERP와 Node DB는 별도 서버이므로 두 서버를 하나의 트랜잭션으로 잠그지는 않습니다.

실제 닷홈 관리자 세션·FTP·Render 운영 권한은 이 작업 환경에 없어 실제 설치/배포와 인증된 회사 자료 대조는 별도로 필요합니다. 공개 ERP 스키마와 실제 사이트가 다르면 추가 매핑이 필요할 수 있습니다. 실제 휴대폰 설치·GPS 테스트는 이번 검증에 포함하지 않습니다.

## 검증

서버 자동 테스트 199개가 통과했습니다. 실제 PHP 8.3.36 + MariaDB 10.11, 공개 ERP 원본 DDL과 가상 전표로 목록 상태·원본 금액·부분 선택·재시도 중복·ERP 수정 차단·기사 권한·모바일 명세서·단가 자동 채움·ERP 작성 스냅샷·다중 페이지 완전성·페이지 사이 변경 감지를 포함한 11개 통합 검증이 통과했습니다. 운영 회사 자료를 사용하거나 운영 전표를 생성하지 않았습니다.
