# 판매조회 목록·휴대폰 거래명세서 — 1.13.0(23)

설치와 실제 ERP 저장소 진단은 [자체 ERP 원본 연결 안내](ERP_1_13_NATIVE.md)를 먼저 확인하세요. 7개 PHP 파일을 함께 갱신하며 원래 ERP 편집기·도우미·DB 설정·연결키는 유지합니다.

1. 관리자 **전표** 화면을 열면 거래처·품목을 자동 갱신합니다. 검색창에서는 ERP에 직접 조회합니다.
2. **판매 조회 일자 → 일자 조회**로 해당 날짜의 전체 판매목록을 읽습니다. 회사 원본 보관 전표는 **ERP 보관 전표**로 표시하며 일반 작성중·확정·취소 전표와 구분합니다.
3. 전표번호를 누르면 ERP의 현재 원본·마지막 저장 수정본을 다시 읽어 판매전표 확인 화면을 채웁니다. 휴대폰은 가로 넘김 없는 세로 품목 카드로 표시합니다.
4. 공급자·거래처·주소·연락처·계좌·잔액·기재 사항과 품목·수량·단가·공급가액·부가세·합계·공장도가·DC율·DOT를 확인합니다. 원본에 없는 금액은 미확인으로 남깁니다.
5. 배송 정보를 확인하고 **확인하고 전표 등록**을 누르거나 목록에서 여러 전표를 선택해 배차 대기에 등록합니다. 원본이 바뀌었으면 최신 내용을 다시 확인합니다. 조회만으로 배송지는 생성하지 않습니다.
6. **등록한 전표로 지역별 배차 추천**으로 구·시·군 기준 코스를 추천합니다. 관리자 **명세서**, **내역**, 배송 상세에서 보관 명세서를 다시 볼 수 있습니다.

원본 조회·앱 등록은 ERP 판매를 다시 만들거나 재고를 차감하지 않습니다. 앱에서 새로 수기 작성하는 판매는 별도 일반 ERP 작성중 전표이며 원본 보관 전표 작성 기능과 구분합니다. 기존 전표의 가격은 현재 상품 가격으로 덮어쓰지 않습니다. 신규 품목의 소매·도매 참고 가격도 부가세 기준이 확인되지 않았으면 확정 단가로 자동 적용하지 않습니다.

ERP/Node의 오류·파일 누락·버전 불일치는 정상 0건으로 처리하지 않습니다. [실제 전표 대조](ERP_1_13_NATIVE.md#실제-전표-대조와-오류-구분)에서 최근 실제 표시 번호 또는 원본 ID로 확인합니다. 관리자 앱 삭제는 앱 데이터에 적용하며 ERP 원본을 삭제하지 않습니다. 조회 목록·등록 명세서·중복 방지 기록을 유지하려면 서버 `APP_DATA_DIR`을 영속 보관해야 합니다.
