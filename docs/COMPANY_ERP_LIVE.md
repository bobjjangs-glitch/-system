# 회사 닷홈 ERP 직접 연결 — Android 1.8.0(18)

회사 ERP `https://bobjjangs1231.dothome.co.kr/tire/erp/index.php`의 거래처·품목·확정 판매전표를 조회하는 기능입니다. E카운트 Open API와 별도입니다. E카운트 인증 정보는 필요하지 않습니다.

현재 실제 주소에서는 ERP 로그인 화면을 확인했습니다. 사용자의 공개 [ERP 소스](https://github.com/bobjjangs-glitch/erp)에서 테이블과 권한 구조를 확인해 연결용 PHP 3개와 Node 조회 어댑터를 구현했습니다. **실제 닷홈 FTP 업로드·연동키 설정·실제 데이터 확인은 아직 완료되지 않았습니다.**

## 사용 방식

- 관리자 전표 화면의 **거래처 목록 가져오기 / 품목 목록 가져오기**는 파일 창을 열지 않고 회사 ERP를 새로 조회합니다. 여러 페이지를 모두 확인한 후 검색용 목록을 교체합니다.
- 직접 입력·전표 검토의 **거래처 검색 / 품목 검색**도 연결 설정이 있으면 ERP를 직접 검색합니다. 거래처명·주소·연락처, 품목명·규격·코드를 채웁니다. 참고 단가는 ERP 도매단가이며 전표 총액으로 계산하지 않습니다.
- **판매 조회 일자 → 판매조회 내역 가져오기**는 DB의 `trade_date`로 날짜를 골라 현재 확정 전표를 읽습니다. 한 전표의 여러 품목을 묶어 거래처·주소·연락처·수량·합계금액을 검토 화면에 넣습니다. 배송 예정일은 앱 상단에서 선택한 날짜입니다.
- `draft`(작성중)·`canceled`(취소)는 제외한 개수를 알립니다. 음수/0 수량이 있는 반품·혼합 전표는 **전표 전체를 제외**하고 안내합니다. 원본을 확인해 필요한 배송지만 직접 등록하세요.
- 주소·연락처 누락은 경고하고 검토 중 입력할 수 있습니다. 임의 주소·수량·금액을 만들지 않습니다. ERP의 현재 거래처 주소를 사용하며 별도의 과거 배송주소 열은 공개 소스에서 확인되지 않았습니다.
- **검토 후 배송지 등록**을 눌러야 저장됩니다. 판매전표 ID를 유지해 반복 조회·동시 검토 시 중복 배송지 저장을 막습니다. 이미 등록한 배송지는 ERP 수정으로 자동 덮어쓰지 않습니다.
- 조회 실패·인증 실패 시 저장 자료를 실시간 결과로 바꾸어 표시하지 않습니다. 조회 시각을 표시하며, 연결 해제 후 남아 있는 스냅샷은 `회사 ERP 저장 자료`로 구분합니다.
- 실시간은 **버튼/검색 실행 시 최신 조회**를 뜻합니다. 앱이 닫힌 동안 자동 전표 생성·웹훅·상시 동기화는 구현하지 않았습니다.

## 닷홈 설치

필요한 기존 ERP를 백업한 뒤 제공된 연동 ZIP을 풉니다. 기존 `tire/erp`에 다음 파일을 추가합니다.

```text
tire/erp/dispatch_api.php
tire/erp/dispatch_setup.php
tire/erp/inc/dispatch_bridge.php
```

기존 DB 설정 `inc/config.php`는 ZIP에 들어 있지 않습니다. 직접 패키지를 만들려면 `python3 scripts/package-company-erp.py`를 사용합니다.

1. ERP **관리자** 계정으로 [배차 연결 설정](https://bobjjangs1231.dothome.co.kr/tire/erp/dispatch_setup.php)에 접속합니다. 일반 사무 계정은 설정할 수 없습니다.
2. **연동키 발급**을 누릅니다. 새 키는 해당 응답에서 한 번 표시됩니다.
3. Render `bareun-dispatch-test` → **Environment → Edit**에 다음 값을 등록합니다.

| 변수 | 값 |
| --- | --- |
| `COMPANY_ERP_API_URL` | `https://bobjjangs1231.dothome.co.kr/tire/erp/dispatch_api.php` |
| `COMPANY_ERP_TOKEN` | ERP 설정 화면에서 발급한 연결키 |

4. 필요한 무료 Render 내역을 백업하고 `codex/free-node-test` 최신 커밋을 **Manual Deploy → Deploy latest commit**으로 배포합니다. 무료 서비스의 `/tmp` 자료는 재배포 때 없어질 수 있습니다.
5. 새 앱에서 **연결 상태 새로고침 → 거래처 목록 가져오기**를 누릅니다. 설정 유무만으로 인증 성공으로 표시하지 않으며 실제 조회 성공을 확인해야 합니다.
6. 알려진 거래처 1개와 해당 날짜의 실제 전표를 ERP 원본과 비교해 주소·연락처·품목·수량·금액을 확인합니다.

카페24 서버에서도 같은 환경변수를 비공개 `server.env`에 등록하고 PM2를 재시작합니다. 키를 바꾸면 서버를 재시작해야 합니다. ERP에서 키를 재발급하면 이전 키가 차단되므로 Render도 갱신하세요. `inc/dispatch_bridge.private.php`는 연결키 해시와 ERP 식별자를 보관하며 서버 관리자가 보존하고 공개 저장소에는 올리지 않습니다.

## 권한과 처리 범위

ERP API는 고정된 GET 조회만 허용하며 연결키는 HTTPS 요청 헤더로 보냅니다. 앱 번들·상태 API·URL 쿼리에 비밀키를 넣지 않습니다. ERP에는 키 원문 대신 해시를 저장하고, 설정 파일은 실행 캐시를 거치지 않고 데이터로 읽어 재발급을 즉시 반영합니다. 키 발급은 기존 ERP 관리자 세션과 CSRF 검증을 사용합니다.

거래처는 활성 `customer/both`, 품목은 활성 자료를 조회합니다. 거래처 코드는 `partner_code` 열을 먼저 사용하며, 그 열이 없으면 `ecount_code` 열을 사용합니다. 코드 열이나 값이 없으면 공란입니다. 원가·재고·은행정보·계정 비밀번호는 조회 결과에 포함하지 않습니다. SQL은 읽기 전용 트랜잭션에서 실행합니다. ERP 전표를 수정·확정하거나 재고를 움직이는 엔드포인트가 없습니다.

목록은 페이지별 변경 표식을 검사합니다. 조회 중 자료 변경·누락·중복이 감지되면 저장 목록을 유지하고 재조회를 요청합니다. 최대 20,000개 검색 자료, 한 번에 2,000개 판매전표, 페이지당 최대 10,000개 전표 품목을 처리합니다. 큰 자료가 45초 안에 모두 조회되지 않으면 오류로 끝내고 기존 자료를 유지합니다. 단일 검색은 최대 30개를 표시합니다. 실제 호스팅 속도의 보장값은 아닙니다.

조회 당시 정규화한 판매전표 JSON을 관리자 업로드 내역에 보관합니다. 이 파일은 ERP 원본 화면을 촬영한 사진이나 원본 엑셀을 의미하지 않습니다. 등록한 배차·배송 이력과 가져오기 중복 기록의 삭제 규칙은 기존 전표 기능을 따릅니다.

## 검증

실제 PHP 8.3 + MariaDB 10.11에 회사 데이터와 무관한 503개 거래처·판매전표를 넣어 SQL을 실행했습니다. PHP의 DB 사용자는 SELECT 권한만 가집니다. 전체 페이지 조회, 최신 수정 검색, 변경된 페이지 차단, 날짜·상태 필터, 물품·금액 매핑, 검토 후 저장, 중복·조작 차단, 관리자/기사 권한, 키 발급의 관리자·CSRF 확인, 즉시 키 폐기와 모바일 화면을 검증했습니다. 별도 자동 테스트는 응답 오류·과대 응답·원자적 갱신·취소 처리를 검사합니다.

이 결과는 실제 닷홈에 파일이 설치됐거나 실제 회사 자료 연동이 완료됐다는 뜻이 아닙니다. 실제 운영 ERP가 공개 소스와 다른 열/테이블 구조를 사용하면 배포된 구조를 확인해 매핑을 조정해야 합니다.
