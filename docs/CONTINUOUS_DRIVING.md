# 바른배차 1.2.1 — 연속 운행과 GPS 도착 자동 완료

## 휴대폰 시작

기존 앱 위에 새 APK를 설치한다. 앱 ID와 테스트 인증서를 유지하며 로그인·배송 데이터를 초기화하지 않는다. 위치 서비스의 이전 등록은 업데이트 후 한 번 정리하므로 위치 공유를 다시 켠다.

1. 기사 PIN으로 로그인한다. 네이버 지도 앱도 설치되어 있어야 한다.
2. 출발 전이면 `코스 출발 · 네이버 연속 안내`, 이미 운행 중이면 `네이버로 남은 코스 연속 안내`를 누른다.
3. 정확한 위치·백그라운드 위치(항상 허용)·알림 권한을 허용한다. 설정 화면에서 바른배차로 돌아오면 위치 서비스를 준비한 뒤 네이버 내비를 연다.
4. 다음 배송지에서 조건을 만족하면 바른배차가 백그라운드에서 배송 완료를 기록한다. 매 배송마다 바른배차로 돌아와 완료 버튼을 누를 필요가 없다. 앱을 최근 앱 목록에서 강제로 종료하면 위치 공유가 중단된다.

## 외부 내비의 경유지 수

연속 경로는 네이버의 공식 `nmap://navigation` URL을 사용한다. [공식 URL Scheme 문서](https://guide.ncloud-docs.com/docs/en/maps-url-scheme)의 `v1`~`v5` 경유지와 목적지를 전달한다. 현재 위치가 출발점이며 완료·미배송으로 처리된 지점은 새 경로에서 제외한다. 좌표가 잘못됐거나 지원 지역 밖이면 외부 앱을 열기 전에 알려 준다. 네이버가 없을 때 잘못된 웹 길찾기 URL로 대신 열지 않는다.

배송지가 5곳이면 5곳을 경유지로, 회사를 최종 목적지로 지정해 한 번에 안내한다. 더 긴 코스는 경유지 5곳+배송 목적지 1곳씩 나눈다. 예를 들어 배송지 10곳은 1~6번 안내 뒤 7~10번과 회사 복귀를 이어서 안내한다. 6곳이면 배송지 1~6번 구간과 회사 복귀 구간을 각각 열고, 15곳이면 1~6번·7~12번·13~15번 및 회사 복귀의 총 3구간, 20곳이면 총 4구간을 연다. 구간 마지막 배송이 자동 완료되면 `다음 경로 구간` 알림이 나오며, 이 알림을 한 번 눌러 다음 네이버 내비 경로를 연다.

앱의 네이버 전체 지도는 외부 내비 URL의 경유지 제한과 관계없이 배정된 모든 배송지를 표시한다. 기사별 배차 가능 수는 기본 10곳, 관리자 설정상 최대 200곳이다. 서버의 실시간 교통 배차 계산은 별도 [Directions 15 API](https://api.ncloud-docs.com/docs/application-maps-directions15)를 사용하며, 요청당 경유지 15개 한도를 지켜 분할한다. 이 15개는 네이버 지도 앱을 여는 URL의 경유지 수와 다르다.

배송지 15곳을 한 기사에게 배정하려면 관리자 `기사 → 기사 정보 수정 → 한 코스 최대 배송지 수`를 15 이상으로 저장한다. 전체 지도에는 15곳과 회사 왕복이 한 번에 표시되지만 외부 네이버 내비는 위의 3구간으로 안내한다.

이 구간 전환에는 알림을 누르는 동작이 필요하다. Android가 백그라운드 앱의 임의 화면 실행을 제한하므로 자동으로 외부 앱을 강제 실행하지 않는다. 경유지 한도를 우회하는 비공식 파라미터도 쓰지 않는다. 개별 배송지 길안내는 회사 설정의 내비를 사용하고, 연속 경유지 안내 버튼은 네이버 지도를 사용한다.

## 자동 완료 조건

`GPS 도착 시 자동 배송 완료`는 기사가 켜거나 연속 안내를 시작할 때 활성화한다. 운행 중인 자기 코스의 현재 배송지만 처리한다.

- 목적지 반경 80m 안에서 30초 이상 머물러야 한다.
- 정확도 50m 이하의 최신 좌표와 최소 3회 수신을 요구한다. 빠르게 지나가는 위치는 제외한다.
- GPS 수신이 오래 끊기거나 반경을 벗어나면 체류 시간을 다시 측정한다.
- 완료 후에는 실제 완료 지점에서 벗어난 뒤 다음 배송지의 도착을 측정한다. 같은 건물·가까운 연속 배송은 확인 후 `직접 배송 완료`를 사용한다.
- 오래된 좌표·중복 좌표·역순 좌표로 완료를 앞당기지 않는다.
- 서버가 완료 처리한 뒤 응답만 끊긴 경우 다음 조회에서 처리 여부를 확인해 같은 장소의 다음 주문이 연쇄 완료되지 않게 한다.
- 출발 전, 회사 복귀 중, 복귀 완료 상태에서는 배송을 자동 완료하지 않는다. 회사 도착 후 `회사 도착 · 복귀 완료`를 누른다.

GPS 도착 기준의 완료 기록이다. 물품 인수 여부를 직접 확인해야 하는 업무에서는 자동 완료를 끄고 수동 처리한다. 자동 완료를 꺼도 위치 공유는 별도로 유지한다.

## 위치 공유 종료 현상 보완

사용자가 이전 APK에서 위치 공유를 켠 후 종료되고 재진입도 안 되는 현상을 보고했다. 휴대폰 모델은 갤럭시 A16이며 정확한 Android 버전·종료 로그는 아직 없다. 해당 휴대폰의 원인은 확정하지 않았으며 다음 경로를 보완했다.

- 권한 설정에서 돌아온 뒤 앱이 활성화됐는지 확인하고 위치 서비스를 시작한다. 서비스가 준비되는 동안 앱과 전경 위치 수신을 유지한다.
- 전용 단색 알림 아이콘과 알림 채널을 사용한다. 필수 권한이 준비되지 않으면 전경 공유로 상태를 표시한다.
- 처음 GPS 좌표를 무기한 기다리는 시작 과정을 제거하고 위치 수신 구독부터 준비한다.
- 이전 위치 작업을 네이티브 초기화 전에 정리하고 새 버전의 작업 이름으로 등록한다. 사용자 세션·회사 데이터는 지우지 않는다.
- 서비스 예외와 Android 11 이상의 이전 종료 정보를 앱 내부에 기록한다. 관련 오류 후 재실행 시 위치 작업을 정리해 재활성화할 수 있게 한다.
- 로그인 화면과 기사 화면에 `오류 정보 공유`를 제공한다. 모델·Android 버전·오류 내용을 사용자 선택으로 공유하며 자동 업로드하지 않는다.

1.2.1에서는 SDK의 Android 서비스 시작 코드도 수정했다. 기존 SDK는 서비스에 바인딩된 뒤 Android 메인 스레드에서 `startForeground`를 호출하므로 연결 지연에 따른 시작 시간 초과와 권한 거부 예외가 JavaScript 오류 처리 밖에서 발생할 수 있었다. `patches/expo-location+57.0.22.patch`를 `npm ci` 후 자동 적용하며 해당 패키지 버전을 고정한다. Expo 57의 사전 컴파일된 AAR 대신 수정한 소스를 빌드하도록 `package.json`의 `expo.autolinking.android.buildFromSource`에 `expo-location`을 지정한다. 이 설정 없이 소스 패치만 적용하면 APK에 수정이 포함되지 않는다.

- 서비스 자체의 `onStartCommand`에서 즉시 알림과 함께 시작한다. 바인딩 콜백을 기다리지 않는다.
- 네이티브 서비스의 권한·시작 오류를 처리해 종료하고 진단 기록을 남긴다. 등록된 작업 이름만으로 성공했다고 판단하지 않고 실제 실행 상태를 앱에서 확인한다.
- 실패 시 작업을 해제하고 앱을 열어 둔 동안의 위치 공유를 유지한다. 외부 내비를 열기 전에는 백그라운드 서비스의 실제 실행을 요구한다.
- 시작 중 로그아웃·중지하면 늦게 도착한 바인딩 콜백을 무시하고 연결을 해제한다. 실패한 서비스의 시작 인텐트를 시스템이 반복 재전달하지 않게 한다.
- 권한 화면에서 돌아온 이벤트가 진행 중인 시작을 취소하지 않도록 한다. GPS가 꺼졌을 때 안내하고, 비정상 좌표·시간을 전송하지 않는다.

갤럭시 A16에는 기존 앱을 삭제하지 말고 1.2.1 APK를 덮어 설치한다. `설정 → 애플리케이션 → 바른배차 → 권한 → 위치`에서 `항상 허용`과 `정확한 위치 사용`을 켜고, 알림도 허용한다. 앱으로 돌아와 기사 코스의 `위치 공유 켜기`를 누른 뒤 지속 알림과 관리자 위치 갱신을 확인한다. 내비로 전환하고 화면을 껐을 때의 수신도 확인한다. 같은 현상이 남으면 `앱 오류 정보 공유`의 기록으로 추가 원인을 확인한다. 캐시·앱 데이터 삭제를 기본 해결책으로 요구하지 않는다.

## 검증 범위

순수 판정 테스트는 도착 시간, 위치 오차, 이동, GPS 끊김, 중복 좌표, 같은 장소의 다음 배송, 코스 상태, 네이버 경유지 제한·순서·회사 복귀를 검증한다. 기존 서버 테스트도 포함한다. 브라우저에서는 임시 데이터와 모의 GPS로 실제 위치 API 업로드 → 자기 코스 조회 → 자동 완료 POST → 서버 상태 변경을 확인한다.

클라우드 Android 16 가상 기기에서는 소프트웨어 에뮬레이션의 시스템·런처 응답 지연이 발생해 사용자 휴대폰의 위치 공유 종료 현상을 동일하게 재현하지 못했다. ARM APK의 x86 번역 계층 오류도 실제 휴대폰 오류로 취급하지 않는다. 네이티브 컴파일·APK 서명·ARM ABI·권한·아이콘 리소스·16KB 정렬 검증과 실제 휴대폰의 GPS·외부 내비·백그라운드 실행 검증은 구분한다.

Android 14·15의 서비스 수명 주기 모의 검증은 `native-tests/`와 `deploy/android/location-service-tests.gradle`을 사용한다. 실제 패치된 SDK 클래스로 즉시 서비스 시작, 권한 거부 처리, 빈 재시작 인텐트, 중지 후 늦은 연결, 바인딩 실패 정리, 시작 거부를 검증한다. 휴대폰 GPS나 삼성 One UI에서의 실행을 증명하는 테스트는 아니다.

1.2.1에서 타입 검사, 순수 로직·서버 테스트 27개, Android 14·15 네이티브 회귀 테스트 12개가 통과했다. 임시 DB와 모의 GPS를 사용한 브라우저 자동 완료·완료 응답 유실 복구도 통과했다. APK 빌드 스크립트는 네이티브 패치와 클라이언트 상태 확인 코드가 실제 APK에 들어갔는지 검사한다.

```bash
source scripts/cloud-android-env.sh
EXPO_PUBLIC_API_URL=https://bareun-dispatch-test.onrender.com NODE_ENV=production EXPO_OFFLINE=1 CI=1 \
  bash android/gradlew -p android \
  -I "$PWD/deploy/android/ldplayer-resource-limits.gradle" \
  -I "$PWD/deploy/android/location-service-tests.gradle" \
  :app:testReleaseUnitTest -PreactNativeArchitectures=arm64-v8a,armeabi-v7a \
  --no-parallel --max-workers=2 --build-cache --console=plain
```
