# 바른배차 1.2.0 — 연속 운행과 GPS 도착 자동 완료

## 휴대폰 시작

기존 앱 위에 새 APK를 설치한다. 앱 ID와 테스트 인증서를 유지하며 로그인·배송 데이터를 초기화하지 않는다. 위치 서비스의 이전 등록은 업데이트 후 한 번 정리하므로 위치 공유를 다시 켠다.

1. 기사 PIN으로 로그인한다. 네이버 지도 앱도 설치되어 있어야 한다.
2. 출발 전이면 `코스 출발 · 네이버 연속 안내`, 이미 운행 중이면 `네이버로 남은 코스 연속 안내`를 누른다.
3. 정확한 위치·백그라운드 위치(항상 허용)·알림 권한을 허용한다. 설정 화면에서 바른배차로 돌아오면 위치 서비스를 준비한 뒤 네이버 내비를 연다.
4. 다음 배송지에서 조건을 만족하면 바른배차가 백그라운드에서 배송 완료를 기록한다. 매 배송마다 바른배차로 돌아와 완료 버튼을 누를 필요가 없다. 앱을 최근 앱 목록에서 강제로 종료하면 위치 공유가 중단된다.

## 외부 내비의 경유지 수

연속 경로는 네이버의 공식 `nmap://navigation` URL을 사용한다. [공식 URL Scheme 문서](https://guide.ncloud-docs.com/docs/en/maps-url-scheme)의 `v1`~`v5` 경유지와 목적지를 전달한다. 현재 위치가 출발점이며 완료·미배송으로 처리된 지점은 새 경로에서 제외한다. 좌표가 잘못됐거나 지원 지역 밖이면 외부 앱을 열기 전에 알려 준다. 네이버가 없을 때 잘못된 웹 길찾기 URL로 대신 열지 않는다.

배송지가 5곳이면 5곳을 경유지로, 회사를 최종 목적지로 지정해 한 번에 안내한다. 더 긴 코스는 경유지 5곳+배송 목적지 1곳씩 나눈다. 예를 들어 배송지 10곳은 1~6번 안내 뒤 7~10번과 회사 복귀를 이어서 안내한다. 구간 마지막 배송이 자동 완료되면 `다음 경로 구간` 알림이 나오며, 이 알림을 한 번 눌러 다음 네이버 내비 경로를 연다.

이 구간 전환에는 알림을 누르는 동작이 필요하다. Android가 백그라운드 앱의 임의 화면 실행을 제한하므로 자동으로 외부 앱을 강제 실행하지 않는다. 경유지 한도를 우회하는 비공식 파라미터도 쓰지 않는다. 개별 배송지 길안내는 회사 설정의 내비를 사용하고, 연속 경유지 안내 버튼은 네이버 지도를 사용한다.

## 자동 완료 조건

`GPS 도착 시 자동 배송 완료`는 기사가 켜거나 연속 안내를 시작할 때 활성화한다. 운행 중인 자기 코스의 현재 배송지만 처리한다.

- 목적지 반경 80m 안에서 30초 이상 머물러야 한다.
- 정확도 50m 이하의 최신 좌표와 최소 3회 수신을 요구한다. 빠르게 지나가는 위치는 제외한다.
- GPS 수신이 오래 끊기거나 반경을 벗어나면 체류 시간을 다시 측정한다.
- 완료 후에는 실제 완료 지점에서 벗어난 뒤 다음 배송지의 도착을 측정한다. 같은 건물·가까운 연속 배송은 확인 후 `직접 배송 완료`를 사용한다.
- 오래된 좌표·중복 좌표·역순 좌표로 완료를 앞당기지 않는다.
- 서버가 완료 처리한 뒤 응답만 끊긴 경우 다음 조회에서 처리 여부를 확인해 같은 장소의 다음 주문이 연쇄 완료되지 않게 한다.
- 출발 전, 회사 복귀 중, 복귀 완료 상태에서는 배송을 자동 완료하지 않는다. 회사 도착 후 `회사 도착 · 복귀 완료`를 누른다.

GPS 도착 기준의 완료 기록이다. 물품 인수 여부를 직접 확인해야 하는 업무에서는 자동 완료를 끄고 수동 처리한다. 자동 완료를 꺼도 위치 공유는 별도로 유지한다.

## 위치 공유 종료 현상 보완

사용자가 1.1.0에서 위치 공유를 켠 후 종료되고 재진입도 안 되는 현상을 보고했다. 해당 휴대폰의 모델·Android 버전·종료 로그가 없어 정확한 원인은 확정하지 않았다. 다음 경로를 보완했다.

- 권한 설정에서 돌아온 뒤 앱이 활성화됐는지 확인하고 위치 서비스를 시작한다. 서비스가 준비되는 동안 앱과 전경 위치 수신을 유지한다.
- 전용 단색 알림 아이콘과 알림 채널을 사용한다. 필수 권한이 준비되지 않으면 전경 공유로 상태를 표시한다.
- 처음 GPS 좌표를 무기한 기다리는 시작 과정을 제거하고 위치 수신 구독부터 준비한다.
- 이전 위치 작업을 네이티브 초기화 전에 정리하고 새 버전의 작업 이름으로 등록한다. 사용자 세션·회사 데이터는 지우지 않는다.
- 서비스 예외와 Android 11 이상의 이전 종료 정보를 앱 내부에 기록한다. 관련 오류 후 재실행 시 위치 작업을 정리해 재활성화할 수 있게 한다.
- 로그인 화면과 기사 화면에 `오류 정보 공유`를 제공한다. 모델·Android 버전·오류 내용을 사용자 선택으로 공유하며 자동 업로드하지 않는다.

## 검증 범위

순수 판정 테스트는 도착 시간, 위치 오차, 이동, GPS 끊김, 중복 좌표, 같은 장소의 다음 배송, 코스 상태, 네이버 경유지 제한·순서·회사 복귀를 검증한다. 기존 서버 테스트도 포함한다. 브라우저에서는 임시 데이터와 모의 GPS로 실제 위치 API 업로드 → 자기 코스 조회 → 자동 완료 POST → 서버 상태 변경을 확인한다.

클라우드 Android 16 가상 기기에서는 소프트웨어 에뮬레이션의 시스템·런처 응답 지연이 발생해 사용자 휴대폰의 위치 공유 종료 현상을 동일하게 재현하지 못했다. ARM APK의 x86 번역 계층 오류도 실제 휴대폰 오류로 취급하지 않는다. 네이티브 컴파일·APK 서명·ARM ABI·권한·아이콘 리소스·16KB 정렬 검증과 실제 휴대폰의 GPS·외부 내비·백그라운드 실행 검증은 구분한다.
