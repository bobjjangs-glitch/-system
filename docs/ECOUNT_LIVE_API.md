# E카운트 직접 조회 — Android 1.7.0(17)

품목을 읽는 서버 어댑터와 관리자 화면을 구현했습니다. **실제 E카운트 계정의 인증·조회는 아직 검증하지 않았습니다. 거래처·판매내역 실시간 조회는 현재 지원되지 않습니다.** 등록/판매 입력 API를 조회에 사용하지 않으며 ERP 자료를 쓰거나 변경하지 않습니다.

## 현재 가능한 범위

2026-11-06 사용자가 확인한 메뉴는 `거래처 등록, 품목 등록, 품목 조회, 판매 입력`입니다. [공식 Open API 공개 안내](https://www.ecount.com/kr/ecount/product/erp_open-api)도 품목은 조회, 거래처 등록·판매는 입력으로 안내합니다. 상세 명세와 계정별 권한은 로그인 후 공식 매뉴얼에서 확인해야 합니다.

| 자료 | 현재 구현 | 필요한 후속 작업 |
| --- | --- | --- |
| 품목 | 서버에서 목록 조회, 정확한 품목코드로 직접 조회 | 서버 인증 설정, 계정 매뉴얼과 실제 응답 확인 |
| 거래처명·주소·연락처 | 직접 조회 미지원; 기존 저장 자료 검색 가능 | 거래처 조회 API 또는 공식 연동 방법 확인 |
| 날짜별 판매전표 | 직접 조회 미지원; 명시적으로 선택한 엑셀만 검토 후 등록 | 날짜별 판매 조회 API 또는 공식 연동 방법 확인 |

품목 목록 버튼은 파일 선택 창을 열지 않습니다. 목록을 조회해 검색용 자료로 저장하며 조회 시각을 표시합니다. 다시 누를 때 제한 시간이 남아 있으면 **새로 조회하지 않았다는 안내와 기존 시각**을 표시합니다. 자동 상시 동기화는 구현하지 않았습니다. 품목 검색의 `정확한 품목코드 → 품목코드로 직접 조회`는 매번 해당 코드의 API 응답을 받아 선택할 수 있습니다. 품목명으로 저장 자료를 찾는 기능은 별도로 표시합니다.

목록 호출은 서버에서 보수적으로 최소 10분, 개별 조회는 최소 1.1초 간격을 적용합니다. 이는 이번 구현의 제한이며 해당 계정의 공식 허용 횟수나 실시간 보장값을 뜻하지 않습니다. 계정 매뉴얼에 더 엄격한 제한이 있으면 적용 전에 조정해야 합니다. API에서 제한·인증 오류·확인하지 못한 형식이 오면 성공으로 표시하지 않습니다. 실패 시 같은 계정의 이전 자료를 보존하고 이전 시각을 표시합니다.

## Render 설정

1. 필요한 기존 전표·배송 내역을 먼저 백업합니다. 무료 Render의 `/tmp` 자료는 재배포 때 지워질 수 있습니다.
2. Render 서비스 `bareun-dispatch-test` → **Environment → Edit**에서 다음을 등록합니다. **값은 서버 환경 설정에만 입력하세요. 앱·채팅·저장소에 넣지 않습니다.**

| 변수 | 값 |
| --- | --- |
| `ECOUNT_COM_CODE` | E카운트 회사코드 |
| `ECOUNT_USER_ID` | Open API 사용 권한이 있는 사용자 ID |
| `ECOUNT_API_CERT_KEY` | 해당 운영/테스트 환경의 API 인증키 |
| `ECOUNT_ENV` | 실제 회사 자료는 `production`, 테스트 인증키는 `sandbox` |

3. Save 후 소스 브랜치 `codex/free-node-test`의 최신 커밋을 **Manual Deploy → Deploy latest commit**으로 배포합니다. 이 서비스는 자동 배포가 꺼져 있습니다. 인증키 변경 시에도 재시작이 필요합니다.
4. E카운트의 API 신청, 사용자 조회 권한, 허용 IP 제한을 계정 매뉴얼대로 확인합니다. IP 등록이 필요하면 휴대폰 IP 대신 Render의 해당 서비스에서 안내하는 서버 송신 IP를 사용합니다.
5. 관리자 `전표 → E카운트 직접 연결`에서 `인증 설정됨 · 첫 조회로 연결 확인 필요`를 확인합니다. **설정 유무만으로 인증 성공이라고 표시하지 않습니다.** `E카운트 품목 목록 조회`가 성공해야 연결을 확인한 것입니다.
6. `배송지 직접 입력 → 품목 검색`에서 실제 품목코드 하나를 직접 조회해 이름·규격·참고 단가를 ERP 원본과 비교합니다. 단가는 전표 금액으로 자동 계산하지 않습니다.

카페24는 비공개 `server.env`에 같은 값을 등록하고 PM2 서비스를 재시작합니다. 인증키와 세션은 API 상태 응답·앱 번들에 포함하지 않습니다. API 로그인 세션은 서버 메모리에만 보관합니다.

## 거래처·판매내역 조회를 위한 문의

아래 내용을 E카운트 고객센터나 담당자에게 문의해 조회용 공식 명세를 확인해야 합니다.

> 외부 배송앱에서 거래처명·코드·배송주소·연락처와 날짜별 판매전표(판매번호·거래처·품목·수량·금액)를 조회하려 합니다. 현재 Open API 메뉴에는 거래처 등록, 품목 등록/조회, 판매 입력만 보입니다. 거래처/판매내역을 읽는 공식 API 또는 승인된 자동 연동 방법이 있나요? 등록/판매 입력 기능이 아닌 조회 기능과 조회 일자·변경 내역·취소/반품 처리 방법이 필요합니다.

공식 조회 방법이 확인되면 그 명세에 맞춰 연결할 수 있습니다. 인증키만 등록한다고 존재하지 않는 조회 기능이 생기지는 않습니다. 지금은 거래처·판매 조회 요청에 미지원 안내를 반환하며, 등록/판매 입력 API나 로그인 화면 자동 수집으로 대체하지 않습니다.

## 구현 및 검증 범위

서버는 운영/테스트 Zone 조회 → API 로그인 → `InventoryBasic/GetBasicProductsList` 또는 `InventoryBasic/ViewBasicProduct`만 호출합니다. 경로·필드는 공개 구현과 대조했으나 실제 계정의 최신 공식 상세 매뉴얼/응답으로 추가 확인해야 합니다. 외부 응답의 임의 호스트로 인증 정보를 보내지 않습니다.

가짜 API 응답으로 인증 누락·운영/테스트 호스트·세션 재사용·호출 제한·재시작·오류 원문 비노출·응답 검증·캐시 보존·계정 변경·관리자 권한을 테스트합니다. 실제 계정 연동 성공, 전체 ERP 자료의 완전성, 미지원 거래처/판매 조회가 완료됐다는 의미는 아닙니다.
