# 자체 ERP 원본 판매전표 연결 — 1.13.0(23)

기존 연동은 일반 판매 저장소인 `erp_trades`를 읽었습니다. 사용 중인 판매 수정 화면은 `native_trade_edit.php`이며, 이 화면의 원본은 별도 보관 저장소인 `erp_ecount_documents`에 있습니다. 1.13은 제공받은 실제 편집기와 조회 도우미의 처리 순서에 맞춰 이 저장소를 읽습니다. 테이블 이름에 `ecount`가 있어도 회사 ERP DB에 보관된 자료이며, 외부 E카운트 API를 호출하는 기능은 아닙니다.

## 어떤 내용을 읽는가

- `erp_ecount_documents.current_version_id`가 가리키는 현재 원본과 `erp_ecount_doc_lines.row_json`을 읽습니다. 더 큰 버전 ID가 있다는 이유로 현재 원본을 바꾸지 않습니다.
- 해당 문서·현재 버전에 저장된 `erp_ecount_trade_edits`의 마지막 수정본을 적용합니다. 편집기의 `header_saved` 규칙에 따라 사용자가 지운 빈 값도 구분합니다.
- 회사 프로필·거래처·명세서·품목·공장도가·DOT 정보는 설치된 원래 ERP 조회 도우미로 채웁니다. 현재 품목 가격으로 기존 전표의 수정된 가격을 덮어쓰지 않습니다.
- 표시 전표번호와 내부 자료 번호(`source_doc`)를 구분합니다. 화면의 전표번호가 내부 자료 번호와 달라도 실제 표시 번호로 찾을 수 있습니다. ERP 판매일자와 전표번호 날짜가 다르면 두 날짜를 보존합니다.
- 공급자, 거래처코드·상호·대표자·사업자번호·연락처, 담당자·출하창고·거래유형·통화·계좌·잔액·배송지·기재 사항과 각 품목의 원본 항목을 전달합니다. 수량·단가·공급가액·부가세·합계·공장도가·DC율·비고·DOT도 포함합니다.

원본에 없는 금액은 **미확인**으로 유지합니다. 부가세를 일괄 10%로 만들거나 모르는 금액을 0원으로 바꾸지 않습니다. 명시된 영세율·면세·0원도 구분하며, 원본 항목의 숫자 문자열과 소수 값을 함께 보관합니다. 화면의 원화 표시는 ERP와 같이 반올림할 수 있습니다. 원본 보관 전표의 상태는 **ERP 보관 전표**이며 작성중·확정 여부를 추측하지 않습니다. 배송 등록은 양수 수량과 확인된 음수 아닌 합계 등 배송 조건을 검사하며, ERP 회계 처리로 간주하지 않습니다.

## 설치

ERP PHP 7개, Node 서버, 앱을 함께 갱신합니다. Render 인증·배포는 사용자가 진행합니다. 기존 연동키는 계속 사용합니다.

### 자동 적용 파일을 사용하는 경우

1. 제공된 자동 설치 ZIP의 `bareun_update_1_13.php`를 FTP의 기존 `tire/erp` 폴더에 올립니다. `index.php`와 `inc`가 있는 위치입니다.
2. ERP 관리자 계정으로 로그인한 뒤 `https://bobjjangs1231.dothome.co.kr/tire/erp/bareun_update_1_13.php`를 엽니다.
3. **백업하고 ERP 파일 7개 적용**을 누릅니다. 설치기는 대상 파일의 해시·백업·교체를 확인하고, 실패 시 교체한 파일을 복구합니다. 성공하면 설치기는 삭제되고 연결 확인 화면으로 이동합니다.
4. 아래의 실제 전표 대조를 진행한 뒤 Render의 `codex/free-node-test`에서 해당 릴리스 커밋을 배포하고 1.13.0(23) APK를 설치합니다.

### 직접 교체하는 경우

`bareun-company-erp.zip`의 폴더 구조를 유지하여 다음 **7개 전부**를 기존 `tire/erp` 아래 같은 경로에 추가·교체합니다.

| 경로 | 역할 |
| --- | --- |
| `dispatch_api.php` | 인증된 읽기 API |
| `dispatch_setup.php` | ERP 관리자 연결·조회 진단 |
| `dispatch_sale.php` | 별도 일반 판매 작성 API |
| `inc/dispatch_bridge.php` | 자료 구분·기존 연동 |
| `inc/dispatch_sales.php` | 별도 일반 판매 작성 처리 |
| `inc/dispatch_native.php` | 실제 원본 전표·현재 수정본 읽기 |
| `inc/dispatch_catalog_native.php` | 실제 거래처·품목 조회 |

기존 `inc/config.php`, `inc/dispatch_bridge.private.php`, `native_trade_edit.php`와 원래 조회 도우미 파일은 교체 대상이 아닙니다. 원본 조회에 필요한 기존 `business_source_service.php`, `native_line_view.php`, `native_sale_partner.php`, `statement_print.php`, `statement_source_service.php`, `company_service.php` 및 이들이 사용하는 도우미는 ERP에 설치된 호환 버전을 유지합니다. 이 사설 ERP 소스는 배포 ZIP에 포함하지 않습니다.

원본 전표 읽기에는 DB 설치·마이그레이션이나 **앱 판매 작성 허용 · 저장소 준비**가 필요하지 않습니다. 이 버튼은 아래의 별도 일반 판매 작성 기능을 켤 때만 사용합니다.

Render 환경변수는 다음과 같습니다. 기존 값이 있으면 유지합니다.

```text
COMPANY_ERP_API_URL=https://bobjjangs1231.dothome.co.kr/tire/erp/dispatch_api.php
COMPANY_ERP_TOKEN=기존 ERP 연동키
```

키를 처음 발급할 때만 ERP 관리자 연결 화면에서 발급합니다. 비밀키는 앱·공개 저장소·채팅에 넣지 않습니다. 서버의 `APP_DATA_DIR`은 내역과 등록 기록을 보관할 영속 저장소로 운영합니다.

## 실제 전표 대조와 오류 구분

1. ERP 관리자로 [연결 확인 화면](https://bobjjangs1231.dothome.co.kr/tire/erp/dispatch_setup.php)을 엽니다. **현재 조회 저장소**가 `erp_ecount_documents`, 연동 버전이 `1.13.0`인지 확인합니다.
2. **이 저장소에 실제로 있는 최근 전표**에서 실제 표시 번호를 선택합니다. 예전 예시 번호가 현재 DB에도 있다고 가정하지 않습니다.
3. 사용 중인 판매 수정 주소가 `native_trade_edit.php?id=129470`이면 [원본 ID로 대조](https://bobjjangs1231.dothome.co.kr/tire/erp/dispatch_setup.php?documentId=129470)합니다. `129470`은 문서 ID이며 전표의 마지막 순번이 아닙니다. 다른 전표는 해당 수정 주소의 `id`를 사용합니다.
4. **기존 ERP 전표 화면에서 대조하기**로 편집기를 열어 표시 번호·현재 수정 내용·주소·연락처·품목·금액을 비교합니다. 같은 표시 번호를 앱의 **명세서 → 전표번호로 명세서 조회**에서도 확인합니다.

도우미 누락·호환되지 않는 도우미·불완전한 원본 DB는 해당 오류로 중단합니다. 빈 일반 판매 저장소로 몰래 전환해 정상 0건으로 표시하지 않습니다. 0건은 현재 조회한 저장소와 조건에 맞는 전표가 없다는 결과이며, 이때 원본 ID와 최근 전표를 따로 확인합니다. 번호가 중복·모호하면 자동 선택하지 않습니다.

날짜별 조회는 전체 페이지를 읽고 변경 지문을 확인합니다. 날짜 조건은 ERP 일자·자료 번호 날짜·실제 표시 번호 날짜를 함께 대조합니다. 하루 최대 2,000건을 넘거나 페이지 사이 원본이 바뀌면 부분 목록을 성공으로 저장하지 않습니다. 매우 많은 후보가 잡히면 날짜별 조회 대신 원본 ID 진단으로 확인합니다.

## 앱에서 확인하고 배차하기

관리자 전표 화면은 거래처·품목을 자동 갱신하며 검색할 때 ERP를 조회합니다. **일자 조회** 한 번으로 해당 날짜 목록을 읽고, 전표번호를 누르면 현재 원본을 다시 읽어 판매전표 확인 화면을 채웁니다. 배송주소·연락처를 확인한 뒤 **확인하고 전표 등록**으로 앱 배송 전표를 만듭니다. 확인 중 원본이 바뀌면 재확인을 요구합니다. 이어서 등록한 전표의 구·시·군을 기준으로 배차를 추천할 수 있습니다.

ERP에서 읽어 등록한 전표는 판매 입력·확정·재고 차감·수금을 실행하지 않습니다. 등록 당시 명세서는 앱 내역에서 보관하며, 앱 자료를 삭제해도 ERP 원본은 삭제하지 않습니다.

앱에서 **새로 수기 작성**하는 판매전표는 별도 일반 판매 저장소인 `erp_trades`의 작성중 전표입니다. 원본 보관 전표를 새로 만들거나 수정하는 기능이 아닙니다. 이 작성 기능은 ERP 관리자의 별도 허용과 저장소 준비가 필요하며 DB CREATE/ALTER 권한을 사용할 수 있습니다. 판매 확정·재고 처리는 기존 ERP에서 진행합니다. 일반 판매 저장소를 함께 지원할 경우 날짜별 목록은 두 출처를 구분해 함께 보여 주며, 같은 내부 ID라도 서로 다른 전표로 취급합니다.

## 검증 범위와 배포 확인

PHP 8.1 이상과 기존 ERP·조회 도우미가 필요합니다. 개발 검증은 PHP 8.3·MariaDB 10.11에서 제공받은 실제 편집기와 도우미 함수에 가상 DB 자료를 넣어 수행했습니다. 제공되지 않은 부가 서비스는 테스트용으로만 대체했습니다. 현재 버전·마지막 수정본·저장된 빈 헤더·원본 표시 번호·가격·공장도가·부가세 미확인/0%·페이지 완전성·변경 감지·읽기 전후 DB 보존을 확인했습니다.

이 검증은 인증된 운영 자료 조회, 닷홈 FTP 설치, Render 운영 배포, 실제 Galaxy A16 설치·GPS를 확인했다는 뜻이 아닙니다. 배포 후 위의 실제 ERP 전표 대조가 필요합니다. 원래 ERP 도우미가 바뀌면 편집기와 연동의 호환성을 다시 확인합니다. 릴리스 커밋·설치 ZIP/APK의 SHA-256은 해당 릴리스에서 확인하며, 원래 도우미의 버전·해시는 관리자 환경에서 비교합니다. 비밀 설정 파일은 공개하지 않습니다.

개발 환경에서 수동 교체 ZIP은 `python3 scripts/package-company-erp.py /tmp/bareun-company-erp.zip`, 자동 설치 ZIP은 `python3 scripts/package-company-erp-installer.py /tmp/bareun-erp-release`로 생성합니다.
