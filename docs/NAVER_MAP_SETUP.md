# 관리자 네이버 지도와 넘버원타이어 회사 왕복

관리자 대시보드의 운행 지도와 기사 화면의 `전체 경로 미리보기`·`전체 경로 크게 보기`는 네이버 Maps JavaScript SDK를 사용한다. 기사별 코스 색상, 모든 배송지의 순서 번호, 완료·미배송 상태, 실제 수신된 기사 위치를 표시한다. `전체 운행 지도 크게 보기`로 확대하고, 지도 안의 `전체 경로` 버튼으로 회사 출발부터 회사 복귀까지 다시 맞춘다. 특정 기사를 고른 상태에서는 그 기사 코스를 보고, 확대 화면에서 `전체 기사 코스 보기`로 돌아간다.

Android 1.4.3부터 기사 미리보기와 확대 화면에도 동일한 네이버 지도 설정을 전달한다. 기사 API는 자기 코스와 공개 지도 Key ID만 반환하며 지도 설정 변경은 관리자만 할 수 있다. 서버와 APK를 함께 업데이트하면 관리자가 바꾼 Key ID가 기사 지도에도 반영된다. 이전 서버가 지도 설정을 반환하지 않으면 앱의 기본 공개 Key ID로 네이버 지도를 연다. 관리자 설정에서 키를 비워 둔 경우에는 기본값으로 덮어쓰지 않고 연결 확인 안내를 표시한다.

지도 표시의 배송지 수와 외부 내비의 경유지 수는 구분한다. 앱 전체 지도는 배정된 모든 배송지를 표시하므로 배송지 10곳·20곳을 한 화면에서 볼 수 있다. 기사별 배차 가능 수는 기본 10곳이며 관리자 설정은 최대 200곳이다. 외부 네이버 내비는 한 번에 경유지 5곳과 최종 목적지 1곳을 전달하며, 긴 코스의 구간 처리와 공식 문서는 [CONTINUOUS_DRIVING.md](CONTINUOUS_DRIVING.md)를 따른다.

위치만 갱신될 때 기존 기사 마커와 열린 정보창을 유지하고 사용자가 이동·확대한 화면을 초기화하지 않는다. 최근 2분 이내이고 해당 코스가 운행·복귀 중인 위치만 수신 중으로 표시하며, 그 외에는 회색 마지막 수신 위치로 표시한다. 도로 정보를 받지 못한 선은 점선으로 구분한다.

## 네이버 Application

사용자가 제공한 공개 웹 지도 Key ID가 기본값에 들어 있다. [Naver Cloud Maps Application](https://console.ncloud.com/maps/application)에서 Dynamic Map을 선택하고 Web 서비스 URL에 `https://bareun-dispatch-test.onrender.com`을 등록해야 한다. 회사 서버 주소를 바꾸면 새 주소도 등록한다. 지도 Key ID는 브라우저에 노출되는 식별자이며 Key Secret은 지도 표시를 위해 앱에 넣지 않는다.

관리자 `네이버 지도 설정`에서 키를 변경하면 서버의 별도 지도 설정에 저장한다. `NAVER_MAPS_KEY_ID` 서버 환경 변수로 초기값을 지정할 수도 있으며 관리자에서 저장한 값이 우선한다. 지도 설정 변경은 기사 PIN·배송지·배차·운행 상태를 초기화하지 않으며 운행 중에도 할 수 있다.

네이버 문서는 실제 서버의 `/map?provider=naver`에서 제공해 브라우저·Android WebView에서 등록한 HTTPS 출처로 인증한다. SDK는 공식 `ncpKeyId`와 비동기 callback 방식을 사용하며, 네임스페이스가 준비된 뒤 지도를 생성한다. 인증·네트워크 오류나 키 누락 시 설정 안내를 표시한다. [공식 SDK 시작 문서](https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html)를 따른다.

기존 서버에 `/api/map-settings`가 없으면 새 APK에서 지도 설정 저장을 막고 서버 업데이트를 안내한다. 웹 화면과 네이버 지도 문서가 서버에 있으므로 GitHub 업로드 이후 Render에도 최신 커밋을 배포해야 한다. GitHub push만으로 Render 배포가 완료됐다고 판단하지 않는다.

## 회사와 시간 설정

- 회사: 넘버원타이어
- 주소: 대전광역시 동구 물류로14번길 13
- 좌표: 위도 36.2719407, 경도 127.4680343
- 배송지별 예상 체류 시간: 10분
- 기본 길안내: 네이버 지도

사용자가 제공한 [회사 네이버 지도 링크](https://naver.me/FfeYUnX9)의 장소 ID는 36661392다. 네이버 공식 Geocoding에서 주소가 `대전광역시 동구 물류로14번길 13`, 지번이 `구도동 378`인 단일 건물 결과와 위 좌표를 확인했다. 건물번호가 일치하는 [공개 Google 지도 주소 결과](https://maps.google.com/maps?q=%EB%8C%80%EC%A0%84%EA%B4%91%EC%97%AD%EC%8B%9C%20%EB%8F%99%EA%B5%AC%20%EB%AC%BC%EB%A5%98%EB%A1%9C14%EB%B2%88%EA%B8%B8%2013&output=embed)와도 교차 확인했다. 도로 전체만 반환한 주소 검색 결과는 회사 좌표로 사용하지 않는다. 회사 주소의 확인된 좌표는 주소 검색 캐시에도 저장한다.

업데이트 후 회사 설정을 한 번 적용한다. 미완료 코스는 배송지 순서·완료 상태·기사·로그인을 유지하며 회사 위치와 10분 체류를 반영한다. 출발지가 달라진 기존 코스의 도로 형상은 잘못된 도로선으로 남기지 않고 명시적인 근사 경로로 바꾼다. 새로 배차할 때 도로 경로를 다시 조회한다. 완료한 과거 코스는 출발지와 예상 시간을 보존한다. 이후 관리자가 저장한 설정을 매 재시작마다 덮어쓰지 않는다.

앱의 예상 코스 시간은 배송지 수 × 10분과 회사 왕복 주행 시간을 포함한다. 예를 들어 배송지 5곳의 체류 시간은 총 50분이다. 외부 내비가 표시하는 시간은 해당 내비의 주행 시간 계산이다.

기사 연속 안내의 마지막 구간은 넘버원타이어를 최종 목적지로 넘긴다. 배송지가 5곳이면 5곳 경유 후 회사로 돌아간다. 더 긴 코스는 네이버 공식 경유지 한도에 맞춰 나누며 마지막 구간에 회사 복귀를 포함한다. 구간 전환은 알림을 한 번 눌러 이어간다. 자세한 내용은 `CONTINUOUS_DRIVING.md`를 따른다.

## 검증

타입 검사와 서버·로직 테스트 31개가 통과했다. 서버 테스트는 지도 설정의 관리자 권한·저장·재시작 복원·운행 코스 보존, 회사 설정 이전의 순서·상태·과거 기록·로그인 보존, 왕복 경로와 배송지당 10분 체류를 검증한다. 모바일·PC 브라우저에서는 지도 SDK 테스트 대역과 임시 DB로 전체 배송지·회사 복귀 표시, WebSocket 위치 이동, 확대 화면 유지, 기사 선택과 전체 코스, 키 변경 시 운행 보존, 인증 실패 시 설정 열기와 재시도 복구를 검증했다. 최종 Key ID로 실제 Render 출처에서 네이버 공식 SDK·지도 타일·두 개 왕복 코스·배송지 10곳·마커 이동·지연 위치·전체 경로 맞춤을 확인했으며 지도 HTTP 오류는 없었다. 회사 주소 Geocoding도 정상 응답을 받았다. 이 검증은 별도 브라우저의 예시 데이터로 수행하며 운영 서버 배포 완료나 실제 휴대폰 GPS·외부 내비의 물리적 운행을 증명하지 않는다.

iPhone 빌드와 카메라 권한 안내 변경은 사용자가 네이버 지도 작업을 우선 요청해 이번 범위에서 보류했다.
