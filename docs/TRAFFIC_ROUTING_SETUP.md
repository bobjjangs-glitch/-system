# 실시간 교통을 반영한 배차

관리자 배차 화면에서 공통 출발 예정 시각을 정하면 배송지별 예상 도착·출발 시각과 회사 복귀 시각을 계산합니다. 배송지 체류 시간은 관리자 회사 설정의 값(현재 10분)을 사용합니다. 날짜가 다른 배송의 시각도 해당 배송일의 한국 시간으로 저장합니다.

## 서버 설정

1. Naver Cloud의 **Maps Application**에서 **Directions 15**를 사용 설정합니다. 웹 지도의 Dynamic Map Key ID만으로 길찾기를 요청할 수는 없습니다.
2. Render 서비스의 Environment에 다음 두 변수를 저장합니다.
   - `NAVER_DIRECTIONS_KEY_ID`: 해당 Maps Application의 Key ID
   - `NAVER_DIRECTIONS_KEY_SECRET`: 해당 Application의 Key Secret
3. 최신 서버를 배포합니다. Secret을 채팅, 앱 소스, `EXPO_PUBLIC_*`, 웹 지도 설정에 넣지 마세요.

`GET /api/routing-status`는 관리자만 조회할 수 있으며 설정 여부와 필요한 변수 이름만 반환합니다. 설정됨은 인증 성공을 의미하지 않습니다. 실제 길찾기 결과를 정상 수신한 코스에만 `naver-traffic` 표시와 조회 시각을 저장합니다.

Render 무료 서버의 현재 `/tmp` 데이터는 재배포 시 사라질 수 있으므로 필요한 내역을 먼저 저장하세요. 이 변경은 기존 데이터베이스의 계정·전표·완료 코스를 삭제하지 않고 코스 일정 열을 추가합니다.

## 계산 범위와 한계

- 회사 출발→배송지→회사 복귀 전체를 계산합니다. Naver가 같은 출발·도착 좌표를 거절하므로 회사 왕복을 마지막 배송지에서 분할하고, 각 요청은 경유지 15개 이하를 지킵니다.
- 지리적으로 가까운 배송지를 묶은 뒤, 실제 교통 소요시간으로 정방향·역방향을 비교합니다. 기사별 예상 완료시간을 줄이는 제한된 이동·교환 후보도 비교합니다. 모든 조합의 전역 최적해를 보장하지 않습니다.
- 기사 수용량과 배송지 누락·중복 방지를 지킵니다. 전체 배송지 수와 기사별 수용량이 충분하면 기사당 최소 5곳을 유지합니다.
- 배차 한 번에 외부 길찾기 요청을 최대 40회, 동시에 최대 4회로 제한합니다. 요청 제한은 무한한 조합 탐색 및 과도한 API 호출을 막기 위한 것입니다. 동일 구간 조회 결과의 캐시는 30초이며, 만료 결과를 제거하고 최대 64구간만 저장합니다.
- Directions API는 **조회 시점의 교통**을 반영합니다. 미래 출발일의 교통 예측을 요청하는 기능은 없습니다. 다음 날 출발 시각을 정해도 교통 정보는 현재 조회 시점의 자료이며, 앱에도 이를 표시합니다.
- 제공자가 경유지별 시간을 충분히 주지 않으면 전체 교통 소요시간을 구간 거리 비율로 나눠 도착 시각을 추정하고 `legTimesEstimated`로 표시합니다. 코스 총시간과 배송지별 도착 시각 모두 예상치입니다.
- 실시간 모드를 선택했는데 인증·조회가 실패하면 오류를 반환하고 기존 배차를 보존합니다. 이를 일반 거리 추정으로 바꾸어 실시간 결과처럼 보여주지 않습니다. 연동 없이 일반 배차를 선택하면 기존 도로·거리 추정을 사용합니다.

공식 문서: https://api.ncloud-docs.com/docs/application-maps-directions15

사용량·무료 제공 범위와 초과 요금은 Naver 계정 및 상품의 최신 요금표에서 확인하세요. 앱은 과금 계정 등록이나 유료 상품 신청을 대신하지 않습니다.
