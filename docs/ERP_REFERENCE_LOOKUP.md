# 전표번호·원본 ID 조회 — 1.13.0(23)

설치·저장소·필드·검증 범위는 [자체 ERP 원본 연결 안내](ERP_1_13_NATIVE.md)를 따릅니다. 이전 공개 ERP의 일반 판매 테이블만 확인하던 방식과 달리 실제 `native_trade_edit.php`의 현재 원본·최신 수정본을 읽습니다.

앱 관리자 **명세서 → 전표번호로 명세서 조회**에는 현재 ERP 화면에 표시된 전표번호를 입력합니다. 번호의 연도·월·일·순번 표기 차이는 대조하되 모호한 여러 전표를 임의로 선택하지 않습니다. 원본 표시 번호와 내부 자료 번호가 다른 경우도 구분합니다. 날짜별 목록은 ERP 판매일자와 번호의 날짜를 함께 확인하며 서로 다르면 원본 일자를 보존합니다.

ERP 관리자로 [dispatch_setup.php](https://bobjjangs1231.dothome.co.kr/tire/erp/dispatch_setup.php)에 접속하면 현재 조회 저장소·연동 버전·전체 판매 건수와 최근 실제 전표를 확인합니다. 예전 예시 번호를 고정해서 시험하지 말고 이 목록의 실제 번호를 선택하세요. 판매 수정 주소가 `native_trade_edit.php?id=129470`이면 [원본 ID 129470 조회](https://bobjjangs1231.dothome.co.kr/tire/erp/dispatch_setup.php?documentId=129470)로 번호 매핑과 별개로 확인합니다. 문서 ID와 전표 순번은 다른 값입니다.

- **0건:** 현재 표시된 저장소·조회 조건에 일치하는 전표가 없습니다. 최근 실제 전표나 원본 ID를 대조합니다.
- **원본 조회 도우미 누락/버전 오류:** 원래 ERP 도우미와 배포 PHP 7개를 확인합니다. 일반 판매 저장소로 자동 전환해 빈 성공을 만들지 않습니다.
- **JSON 401/403:** ERP 연결키·권한을 확인합니다.
- **HTML 401/403:** 호스팅이 PHP JSON 응답 전에 접근을 거절한 경우입니다. 이를 PIN 오류나 전표 0건으로 표시하지 않습니다.
- **조회 중 변경/상한 초과:** 부분 전표 목록을 저장하지 않으며 다시 조회·범위를 확인합니다.

전표 조회 테스트는 읽기 전용입니다. 연결키를 재발급하거나 판매·확정·재고를 바꾸지 않습니다. ERP 설정 페이지에서 찾은 전표를 앱에서도 같은 표시 번호로 대조하고 공급자·거래처·품목·금액을 확인한 뒤 배차에 등록합니다. 실제 운영 설치·인증된 회사 자료·실물 기기 확인은 개발용 가상 DB 테스트와 구별합니다.
