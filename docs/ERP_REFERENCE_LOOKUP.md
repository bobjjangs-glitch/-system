# 명세서 번호 직접 조회·휴대폰 품목 화면 — 1.11.0(21)

## 조회 방식

관리자 하단 **명세서** 탭에서 `20261106-49` 또는 `20261106-48`을 입력하고 **전표번호로 명세서 조회**를 누릅니다. 이 조회는 화면의 날짜 선택과 별도로 ERP 전표번호를 직접 찾습니다. 해당 전표의 공급자·거래처·배송지·전화·품목·수량·원본 단가·금액·부가세·합계·적요·공장도가·DC율을 표시합니다. **이 명세서를 배차 목록에 넣기**로 해당 한 건만 배차 목록에 올린 뒤 선택 등록합니다.

날짜별 **판매조회 내역 가져오기**는 ERP 판매일자뿐 아니라 전표번호에 포함된 날짜도 확인합니다. 두 날짜가 다르면 ERP 원본 판매일자를 유지하고 전표번호 날짜를 별도로 표시합니다. ERP 판매일자가 없고 번호에 날짜가 있으면 번호를 사용했다는 안내를 표시합니다. 어느 경우에도 조회로 ERP 전표를 수정·확정하거나 재고를 차감하지 않습니다.

이는 회사의 실제 0건 원인을 인증된 운영 자료로 확정했다는 뜻이 아닙니다. 기존 판매일자 조건만으로는 0건이지만 `20261106-48`, `20261106-49`는 존재하는 상황을 **가상 DB로 재현해** 검증했습니다. 실제 ERP 구조·배포 버전·접근 제한이 다르면 아래 진단으로 구분해야 합니다.

## 휴대폰 입력·검색

- **배송지 직접 입력**에서 고객명·차량번호 입력란을 제거했습니다. 기존 ERP 전표에 저장된 고객명·차량번호는 명세서 원본 정보로만 표시할 수 있습니다.
- 좁은 화면의 판매 품목과 명세서는 **세로 카드**로 표시합니다. 가로로 넘길 필요 없이 품목코드·품명·패턴·수량·단가·금액·합계·적요·공장도가·DC율을 읽고 입력합니다. 넓은 화면에서는 기존 표를 유지합니다.
- `2354518`, `235/45r18`, `235/45 R18`은 같은 235/45R18 규격을 검색합니다. 폭·편평비·인치를 따로 비교하며 ERP 규격 필드를 우선합니다. 다른 인치·편평비·긴 숫자와 우연히 같은 숫자가 든 품목코드는 제외합니다. 일반 품목명/코드 검색은 유지합니다.

## 조회 결과와 연결 상태

성공한 조회 시각·건수, 실패한 원인·시각을 서버 DB에 기록합니다. 같은 DB를 보존한 재시작 후에도 기록을 다시 읽습니다. 무료 Render가 임시 DB 자체를 초기화하면 이 기록도 사라지므로 `APP_DATA_DIR`의 영속 보관이 필요합니다.

- 정상 조회 0건: 날짜·전표번호 조건에 맞는 데이터가 없다는 결과입니다. **전표번호로 명세서 직접 찾기**로 이동할 수 있습니다.
- JSON 401/403: ERP 연결키/권한 거절로 안내합니다.
- HTML 401/403: PHP의 JSON 응답 전 단계에서 호스팅 접근이 거절된 경우로 구분하고 HTTP 상태를 안내합니다. 이를 PIN 오류나 0건으로 표시하지 않습니다.
- 이전 Node/PHP 버전: 지원하지 않는 조회를 0건으로 표시하지 않고 최신 파일 적용이 필요하다고 안내합니다.

**명세서 → ERP 연결 확인**은 서버·ERP 연동 버전과 해당 날짜/전표번호 기준 건수 및 ERP 전체 판매 건수를 확인합니다. 비밀키·DB 비밀번호는 반환하지 않습니다.

## 실제 ERP에서 확인하는 순서

1. 회사 ERP/DB를 백업하고 제공 ZIP의 PHP **5개**를 기존 `tire/erp`의 같은 경로에 함께 교체합니다. `inc/config.php`나 연결키 파일은 포함하지 않습니다. **기존 연결키는 유지**합니다.
2. ERP 관리자로 `dispatch_setup.php`에 접속합니다. **ERP 전표 조회 테스트**에서 `20261106-49`를 조회합니다. 같은 ERP DB에서 읽은 전표번호·판매일자·품목 수·합계를 표시하며, 기존 ERP 전표 화면으로 대조하는 링크도 제공합니다. 키·전표·재고를 변경하지 않는 읽기 전용 확인입니다.
3. `20261106-48`도 같은 방식으로 대조합니다. 여기서부터 찾지 못하면 현재 연동 파일이 읽는 ERP 자료/구조가 원본 판매조회와 같은지 확인해야 합니다.
4. Render `codex/free-node-test` 최신 소스를 배포합니다. 필요한 기존 무료 서버 자료는 배포 전에 백업합니다.
5. 갱신된 웹의 **명세서 → ERP 연결 확인 → 전표번호로 명세서 조회**에서 같은 전표를 확인합니다. ERP 설정 페이지에서는 찾지만 여기서는 실패하면 표시되는 접근·인증·버전 오류를 확인합니다. 비밀키를 채팅에 보내지 마세요.
6. Android 1.11.0(21)을 기존 앱 위에 설치합니다. ERP에 저장되어 있는 원본 항목과 실제 휴대폰 표시를 대조합니다.

전표번호 발급도 ERP 판매일자와 전표번호 날짜가 다른 기존 건을 포함해 최댓값을 확인합니다. 같은 번호를 재발급하지 않도록 ERP의 날짜별 카운터와 함께 잠급니다. 수기로 작성한 전표는 여전히 ERP의 작성중 전표이며 판매 확정·재고 차감은 기존 ERP에서 처리합니다.

## 검증 범위

APK 제작 전에 다음 검증을 통과했습니다.

- 서버 자동 테스트 **208/208**: 기존 배차·위치·OCR·권한과 새 번호 조회·타이어 검색·조회 기록 보존·오류 분류 포함.
- 실제 **PHP 8.3.36 + MariaDB 10.11**, 공개 ERP 원본 DDL·가상 자료 **16/16**: 판매일자 조건의 0건 재현, 48/49 직접 조회, 규격 검색 동등성, 단건 배차·중복 방지, 관리자 자체 점검, 접근 거절, 기사 권한, 별도 명세서 메뉴, 320px 세로 화면, 입력란 제거, 수기 저장 및 날짜가 다른 기존 번호를 포함한 5건 동시 발급.
- 0건 화면에서 전표번호 조회로 복구, 이전 Node 서버를 새 기능에서 명확히 차단하는 브라우저 흐름과 ERP PHP 파일 일부만 갱신된 경우의 버전 불일치 안내 포함.

실제 회사 ERP의 인증된 자료를 읽을 키/세션과 FTP·Render 운영 권한은 이 작업 환경에 없습니다. 회사의 실제 48/49 내용을 직접 읽었다고 주장하지 않습니다. 실제 운영 설치·배포와 Galaxy A16 실기기/GPS 확인은 별도로 필요합니다. iOS 작업은 보류 상태를 유지합니다.
