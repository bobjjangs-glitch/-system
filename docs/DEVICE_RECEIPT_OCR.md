# Android 전표 기기 인식

Android 1.4.0부터 촬영·사진 선택 후 한국어 ML Kit로 휴대폰 안에서 글자를 읽습니다. 모델은 APK에 포함됩니다. 인식 결과를 표시하기 전에는 사진 업로드, 서버 OCR, 서버 지원 여부 조회를 기다리지 않습니다.

- 원본을 백그라운드에서 긴 변 2200px 이내로 디코딩하고 방향을 반영합니다.
- 네이티브 인식 작업은 4.5초 제한, 앱의 미리보기 작업은 5초 제한을 적용합니다. 제한은 오래 걸리는 작업을 중단하기 위한 상한이며, 모든 사진을 5초 안에 성공적으로 읽는다는 보장은 아닙니다. Galaxy A16 실제 사진의 성공률과 소요 시간은 실기기로 확인해야 합니다.
- 미리보기는 전환 애니메이션 없이 표시됩니다. 이미지 준비·OCR·한국어 텍스트 추출·검토 미리보기가 로컬에서 이뤄집니다. 글자를 찾지 못하거나 기기에서 실패하면 서버 OCR로 조용히 되돌리지 않습니다.
- 읽은 사진·원문·편집 내용은 사용자와 서버별 앱 전용 저장소에 보관됩니다. 닫은 전표는 ‘기기에 저장된 전표’에서 다시 열 수 있습니다.
- 저장할 때만 사진과 `recognitionSource=android-device`, `recognizedText`를 전송합니다. 최신 서버는 받은 텍스트를 파싱하며 Tesseract 대기열에 넣지 않습니다. 수정한 배송지의 등록은 기존 확인 절차를 따릅니다.
- 서버의 `receiptCapabilities.deviceText`가 없으면 전송을 막고 초안을 보관합니다. 서버를 최신 버전으로 배포하면 저장할 수 있습니다. 서버 저장·통신 시간은 OCR 5초 목표와 별개입니다.
- 사진 원본을 지우지 않습니다. 자체 생성 캐시와 완료한 기기 초안만 정리합니다. 원문이나 비밀값을 진단 로그에 출력하지 않습니다.

웹과 iOS의 기존 서버 OCR 경로는 유지합니다. iOS 내부 설치 빌드는 현재 보류되어 있습니다.

## 검증 범위

실제 Android Kotlin 릴리스 컴파일, 취소·세대 구분·샘플링 네이티브 테스트, 실제 App 함수의 미리보기 무통신·저장 흐름 테스트, 기기 초안 저장소 테스트, 서버 OCR 우회·기존 내역 호환 테스트를 수행합니다. VM·파일시스템 대역 테스트는 실기기 인식 성능 측정을 대신하지 않습니다.

APK 재생성에는 `plugins/withReceiptOcr.cjs`가 필요합니다. `npx expo prebuild --clean --platform android`로 프로젝트를 생성하고 기존 내부 테스트 인증서를 유지해야 덮어 설치할 수 있습니다. Google Maven의 `com.google.mlkit:text-recognition-korean:16.0.1` 번들 모델을 사용하며 별도 OCR API 키는 필요하지 않습니다.
