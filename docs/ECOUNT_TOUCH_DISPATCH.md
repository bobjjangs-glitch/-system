> 1.12.0부터 E카운트 직접 연동과 전용 메뉴는 제거했습니다. 이 문서는 이전 파일 형식/터치 배차의 기록입니다. 현재는 [회사 ERP 자동 조회 안내](ERP_1_12_WORKFLOW.md)와 기본 엑셀 업로드를 사용합니다.

# 터치 배차와 E카운트 파일 가져오기

관리자 **배차 → 터치로 배차하기**에서 배송지 오른쪽 `≡`를 길게 누르세요. 미배차에서 기사로, 기사에서 다른 기사로, 코스 안에서 위아래로 이동할 수 있습니다. 화면 양옆으로 끌면 다른 기사가 나타나고 목록 끝으로 끌면 스크롤됩니다. 미배차 칸으로 돌려놓으면 배정이 해제됩니다. 키보드는 이동 핸들에서 Enter → 화살표 → Enter, Esc 취소를 지원합니다.

놓은 순서를 유지하며 회사 출발·복귀, 배송지 체류 10분을 포함한 거리와 시간을 다시 계산합니다. 계산이 실패하면 기존 배차를 보존합니다. 출발 전 코스만 변경할 수 있고 비활성·운행 중 기사, 기사별 최대 배송지 수 초과, 다른 관리자가 변경한 오래된 화면의 이동은 차단합니다. 터치로 편집한 코스는 추천 배차에서도 기사 배정과 순서를 보존합니다. 위치·교통 API가 필요한 계산에는 기존 서버 인증 설정이 필요합니다.

## 현재 E카운트 연동 범위

**이 문서는 수동 엑셀 기능 안내입니다.** 1.7.0(17)의 품목 API 직접 조회와 거래처·판매 조회의 미지원 범위는 [직접 연결 안내](ECOUNT_LIVE_API.md)를 따릅니다. 엑셀 선택 자체는 실시간 조회가 아닙니다.

2026-11-05 확인한 [E카운트 공식 Open API 안내](https://www.ecount.com/kr/ecount/product/erp_open-api)에는 품목 조회가 있고 판매와 거래처 등록은 입력으로 안내됩니다. 공개 목록에서 판매내역·거래처 조회 API는 확인되지 않았습니다. 세부 매뉴얼은 로그인이 필요합니다. 계정의 Open API 상세 매뉴얼과 고객센터에서 조회 가능 여부·권한·사용 신청을 확인해야 직접 연동 가능 범위를 확정할 수 있습니다. 비밀 인증키를 채팅·앱·소스 저장소에 입력하지 마세요.

관리자 **전표 → E카운트 직접 연결 → 엑셀 파일 가져오기(수동)**:

1. E카운트 거래처 목록에서 이름·코드·주소·연락처를 포함해 엑셀 저장 후 **거래처 엑셀 파일 선택**.
2. 품목 목록에서 코드·품목명·규격·단가를 포함해 저장 후 **품목 엑셀 파일 선택**.
3. 판매조회에서 전표번호(일자-No.)·거래처명/코드·품목명/코드·수량·합계금액을 포함해 저장 후 **판매조회 엑셀 파일 선택**.
4. 전표별 검토 화면에서 거래처·주소·연락처·품목·수량·금액을 확인하고 배송지 등록. 주소만 있어도 등록할 수 있습니다.

**날짜별 가져오기:** `가져올 판매일자 / 출고일`에 `2026-11-05`를 입력하면 `26/11/05-47` 등 해당 날짜의 전표만 가져옵니다. `47`은 전표 순번입니다. `2026/11/05-47`도 같은 전표로 인식하고 연도 표기만 다른 중복을 차단합니다. YY 연도는 2000~2099년으로 해석합니다. 존재하지 않는 날짜는 허용하지 않고, 다른 날짜·날짜 확인 불가 행은 제외한 수를 알려 줍니다. 판매일자와 전표 순번이 다른 열이면 결합할 수 있습니다. 판매번호 또는 판매일자 열을 포함해 저장하세요. 기존 APK가 날짜 필터 없이 올리는 요청은 기존 방식으로 동작합니다.

직접 입력에서는 선택 항목인 `판매번호`에 `26/11/05-47`을 입력하면 전표일·순번·배송 예정일을 함께 보여 줍니다. 같은 전표·거래처로 직접 입력해 저장한 내역도 판매조회 재가져오기에서 제외합니다.

**구·시·군별 배차:** 주소에서 대전 동구·대전 서구·충남 논산시·충남 서천군 등을 구분합니다. 같은 이름의 중구라도 시·도가 다르면 분리합니다. 주소가 불명확하면 `지역 확인 필요`로 표시합니다. 배차 화면의 지역 버튼은 미배차 목록을 필터링합니다. 터치 배차 카드와 코스에도 지역을 표시합니다. 추천 배차에서 `구·시·군별 우선 배차`를 켜면 같은 지역을 우선 묶고 기사 한도·가능한 경우 5곳 하한을 지키며 지역 물량을 나눕니다. 지역과 기사 수가 다르거나 한도를 넘으면 여러 코스로 나뉘거나 인근 지역이 한 코스에 들어갈 수 있습니다. 실시간 교통 비교는 지역 혼합을 늘리는 기사 간 이동을 제한합니다. 전역 최적해나 지역별 전담 기사 고정을 보장하지는 않습니다. 수동 지정 코스는 계속 보존합니다.

배송 예정일은 앱에서 선택한 날짜입니다. ERP 판매일과 다른 날 배송도 가능합니다. 원본 판매 파일은 관리자 업로드 내역에 보관됩니다. 거래처·품목 목록은 검색 자료로 저장되며 원본 목록 파일은 보관하지 않습니다. 검색은 가져온 목록과 최근 저장한 배송 내역을 함께 사용합니다. 직접 입력·사진 인식 검토 화면에서도 **거래처 검색 / 품목 검색**을 사용할 수 있습니다.

## 파일과 금액 처리

- `.xlsx`, `.csv` 첫 시트, 15MB 이하, 최대 10,000개 자료 행·150열. 헤더는 처음 30행 안에 있어야 합니다. CSV는 UTF-8/BOM, UTF-16LE, 한국어 CP949를 지원합니다. `.xls`는 Excel에서 `.xlsx`로 다시 저장하세요.
- 거래처: `거래처코드`, `거래처명`, `주소` 또는 `배송주소`, `전화번호` 또는 `연락처`.
- 품목: `품목코드`, `품목명`, `규격`, `판매단가` 또는 `단가`.
- 판매: `일자-No.` 또는 `전표번호`, `거래처명`/`거래처코드`, `품목명`/`품목코드`, `수량`, `합계금액`. 주소·연락처가 파일에 있으면 우선 사용합니다.
- 같은 전표번호·거래처의 품목을 한 배송지로 묶습니다. 같은 전표에 서로 다른 주소가 있으면 분리 확인을 요청합니다. 판매일자도 문서번호도 없으면 날짜별 가져오기에서 제외합니다. 이전 버전의 날짜 필터 없는 가져오기는 행별로 나누고 동일 파일에 한해서만 중복 확인합니다. 번호를 반드시 포함하는 것을 권장합니다.
- 파일에 포함된 거래처·품목 코드는 해당 코드의 검색 자료를 갱신합니다. 같은 파일에서 같은 코드에 복수 주소·규격이 있으면 모두 보관합니다. 기존 배송 내역은 바꾸지 않습니다.
- 거래처코드 또는 이름이 정확히 한 검색 자료에 대응할 때만 주소·연락처를 자동 연결합니다. 복수 지점 등 모호한 경우 공란과 경고를 남깁니다. 검토 화면에서 검색해 선택하세요. 품목도 코드가 하나로 대응할 때만 보완합니다.
- 금액은 파일의 `합계금액`을 우선 사용하고, 그 열이 없을 때 `금액`, 그 열도 없을 때 `공급가액 + 부가세`를 사용합니다. 공급가액만 있으면 그 기준이라는 경고를 표시합니다. 세율·단가·금액을 임의 추정하지 않습니다. 참고 단가는 전표 총액으로 자동 계산하지 않습니다. 원화만 지원합니다.
- 취소·반품·수량 0 이하 행은 제외하고 알려 줍니다. 잘못된 수량·음수 금액은 검토를 요청합니다. 원본이 틀린 경우 원본부터 확인하세요.
- 이미 저장한 판매전표는 재가져오기에서 제외합니다. 두 검토 화면을 열어도 같은 전표를 두 번 저장할 수 없습니다. 배송지 한 건 삭제만으로 가져오기 기록을 지우지 않습니다. 운행 전 전체 전표를 삭제하면 해당 전표의 중복 기록도 함께 삭제되어 다시 가져올 수 있습니다.
- 검색·파일 가져오기·금액·판매전표 식별 정보는 관리자 전용입니다. 기사에게는 배정된 배송 물품·수량·주소·연락처가 표시됩니다.

## 적용 및 검증 범위

새 API가 포함되므로 서버와 앱을 모두 업데이트하세요. 소스 브랜치는 `codex/free-node-test`, Render에서 **Manual Deploy → Deploy latest commit**을 실행해야 웹에도 적용됩니다. 무료 Render의 `/tmp` 데이터는 재배포 때 지워질 수 있으므로 필요한 내역을 먼저 백업하세요. 실제 E카운트 계정/API 및 실제 단말 터치 검증은 아직 하지 않았습니다. 합성 엑셀·로컬 API·브라우저 터치 이벤트로 검증합니다.
